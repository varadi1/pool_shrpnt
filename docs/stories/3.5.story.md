# Story 3.5: CR-based Temporary Unlock (48-hour auto re-lock)

## Status
Approved

## Story
**As an** Admin or Project Manager,
**I want** to create a Change Request (CR) that temporarily unlocks specific folder groups for 48 hours with automatic re-lock,
**so that** urgent changes can be made to locked folders while maintaining control and audit trail

## Acceptance Criteria
1. Admin/PM can initiate a CR to unlock ReadOnly folder groups (*Szakértők* or *Eredménytermékek*)
2. CR unlock takes effect within 5 minutes and automatically re-locks after 48 hours
3. All CR operations are audited with `CR_OPENED`, `CR_EXPIRES`, `CR_CLOSED` events
4. CR includes mandatory reason field and affected scope specification
5. System tracks CR expiry time and enforces automatic re-lock at expiration
6. Multiple concurrent CRs can exist for different folder scopes within same EM (overlapping CRs for same scope extend the unlock period)
7. Manual early closure of CR is supported before 48-hour expiry
8. CR state is visible in UI with countdown timer to auto re-lock

### Data Models
CR and lock tables [Source: architecture/7-data-model-postgresql-15.md]:
```sql
-- Extend existing lock_state table
ALTER TABLE lock_state ADD COLUMN cr_id UUID REFERENCES change_request(id);
ALTER TABLE lock_state ADD COLUMN cr_expires_at TIMESTAMP WITH TIME ZONE;
ALTER TABLE lock_state ADD COLUMN cr_reason TEXT;

CREATE TABLE change_request (
  id UUID PRIMARY KEY,
  em_id UUID REFERENCES order_em(id),
  scope VARCHAR(50), -- 'experts' or 'deliverables'
  reason TEXT NOT NULL,
  created_by UUID REFERENCES user_account(id),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  expires_at TIMESTAMP WITH TIME ZONE NOT NULL,
  closed_at TIMESTAMP WITH TIME ZONE,
  closed_by UUID REFERENCES user_account(id),
  status VARCHAR(20), -- 'active', 'expired', 'closed'
  audit_correlation_id UUID
);

CREATE INDEX idx_cr_expiry ON change_request(expires_at) WHERE status = 'active';
CREATE INDEX idx_cr_em ON change_request(em_id);
```

### Concurrent CR Behavior
When multiple CRs affect the same scope:
- Latest CR extends the unlock period (union of unlock windows)
- Scope remains unlocked until ALL active CRs expire or close
- Example: CR1 expires at T+24h, CR2 created at T+20h for 48h → scope unlocked until T+68h
- Audit logs track each CR independently
