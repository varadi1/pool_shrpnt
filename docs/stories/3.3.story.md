# Story 3.3: Manual Lock/Unlock (PM UI)

## Status
go

## Story
**As a** Project Manager (PM),
**I want** to manually lock or unlock folder groups at the EM level with a reason,
**so that** I can control access outside of automatic time-based rules when needed

## Acceptance Criteria
1. PM can select folder groups (*Szakértők* or *Eredménytermékek*) to lock/unlock
2. "Reason for action" field is mandatory for all manual operations
3. Manual lock/unlock operations take effect within ≤1 minute on SharePoint/Teams
4. All manual operations are audited with `MANUAL_LOCK_APPLIED` / `MANUAL_LOCK_RELEASED` events
5. Permission matrix from EP-02 is respected (only PM role can perform manual locks)
6. UI provides clear feedback on current lock state and pending changes
7. Manual locks can override automatic time-based locks with proper priority handling
8. API endpoint returns success/failure status with appropriate error messages

Manual locks need to integrate with this existing system and have highest priority.

### Data Models
Extend existing lock tables [Source: architecture/7-data-model-postgresql-15.md]:
```sql
-- Add to existing lock_state table or create new
CREATE TABLE manual_lock (
  id UUID PRIMARY KEY,
  order_em_id UUID REFERENCES order_em(id),
  folder_scope VARCHAR(50), -- 'experts' or 'deliverables' 
  lock_action VARCHAR(20), -- 'lock' or 'unlock'
  reason TEXT NOT NULL,
  applied_by UUID REFERENCES users(id),
  applied_at TIMESTAMP WITH TIME ZONE,
  expires_at TIMESTAMP WITH TIME ZONE, -- Optional expiry
  active BOOLEAN DEFAULT true,
  correlation_id UUID
);

-- Extend lock_state to track lock source
ALTER TABLE lock_state 
ADD COLUMN lock_source VARCHAR(20), -- 'manual', 'automatic', 'cr'
ADD COLUMN lock_priority INTEGER; -- 1=manual, 2=cr, 3=automatic
```
