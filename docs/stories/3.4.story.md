# Story 3.4: Notifications in Lock Lifecycle

## Status
Ready for Review

## Story
**As a** System Administrator,
**I want** automated notifications sent at T-3, T-1, T+0 timepoints and on all lock/unlock events,
**so that** stakeholders are informed about lock state changes and upcoming deadlines

## Acceptance Criteria
1. Recipients include affected Partner Admins/Experts + NEÜ PM
2. Messages are generated from templates stored in the database
3. Delivery status feedback is tracked and reported (EP-08)
4. De-duplication: no duplicate notifications for same event+recipient within 24 hours
5. All notifications are audited with `NOTIFICATION_SENT` metadata
6. Notifications are sent via both email and Teams channels
7. Delivery success rate achieves ≥98%
8. Event-driven architecture supports lock.state.changed, lock.cr.opened, deadline.reminder events

### Graph API Integration
Leverage existing Graph API client from SharePoint integration [Source: architecture]:
```python
# Reuse existing Graph client configuration
from api.services.sharepoint.graph_client import get_graph_client

# Email sending via Graph
async def send_email_via_graph(recipient: str, subject: str, body: str):
    graph = await get_graph_client()
    message = {
        "message": {
            "subject": subject,
            "body": {"contentType": "HTML", "content": body},
            "toRecipients": [{"emailAddress": {"address": recipient}}]
        },
        "saveToSentItems": True
    }
    await graph.users[service_account].send_mail.post(message)

# Teams message via Graph
async def send_teams_message(team_id: str, channel_id: str, content: str):
    graph = await get_graph_client()
    message = {
        "body": {
            "contentType": "html",
            "content": content
        }
    }
    await graph.teams[team_id].channels[channel_id].messages.post(message)
```

Required Graph API permissions:
- Mail.Send (for email notifications)
- ChannelMessage.Send (for Teams channel messages)
- Chat.ReadWrite (for Teams direct messages if needed)

### Data Models
Notification tables [Source: Story 3.2 and architecture]:
```sql
CREATE TABLE notification_template (
  id UUID PRIMARY KEY,
  template_key VARCHAR(50) UNIQUE, -- e.g., 'deadline.t-3', 'lock.manual.applied'
  channel VARCHAR(20), -- 'email', 'teams', 'both'
  subject_template TEXT, -- Email subject with {{variables}}
  body_template TEXT, -- Message body with {{variables}}
  teams_card_template JSONB, -- Adaptive card JSON for Teams
  locale VARCHAR(10) DEFAULT 'hu-HU',
  active BOOLEAN DEFAULT true,
  created_at TIMESTAMP WITH TIME ZONE,
  updated_at TIMESTAMP WITH TIME ZONE
);

CREATE TABLE notification_queue (
  id UUID PRIMARY KEY,
  template_id UUID REFERENCES notification_template(id),
  recipient_email VARCHAR(255),
  recipient_teams_id VARCHAR(255),
  recipient_role VARCHAR(50),
  channel VARCHAR(20),
  variables JSONB, -- Template variables
  priority INTEGER DEFAULT 5,
  scheduled_for TIMESTAMP WITH TIME ZONE,
  status VARCHAR(20), -- 'pending', 'processing', 'sent', 'failed'
  retry_count INTEGER DEFAULT 0,
  created_at TIMESTAMP WITH TIME ZONE
);

CREATE TABLE notification_history (
  id UUID PRIMARY KEY,
  event_type VARCHAR(50),
  event_id UUID, -- Reference to triggering event
  recipient_id UUID,
  channel VARCHAR(20),
  sent_at TIMESTAMP WITH TIME ZONE,
  dedup_key VARCHAR(255), -- For de-duplication
  content_hash VARCHAR(64) -- For audit
);

-- Extended from Story 3.2
CREATE TABLE notification_log (
  id UUID PRIMARY KEY,
  notification_type VARCHAR(50),
  recipient_email VARCHAR(255),
  recipient_teams_id VARCHAR(255),
  channel VARCHAR(20),
  sent_at TIMESTAMP WITH TIME ZONE,
  delivered_at TIMESTAMP WITH TIME ZONE,
  delivery_status VARCHAR(20),
  retry_count INTEGER DEFAULT 0,
  error_message TEXT,
  related_entity_id UUID,
  correlation_id UUID
);
```
