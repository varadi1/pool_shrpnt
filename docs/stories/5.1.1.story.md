### Story 5.1.1: Frontend E2E Stabilization and MSAL Mock Mode

## Status
Draft

## Objective
Make the Admin/PM UI (Story 5.1) reliably testable end-to-end by:
- Preventing real Microsoft login redirects during tests
- Ensuring routes, role gating, and mobile behavior match acceptance tests
- Aligning dashboard widgets with mocked API responses in tests
- Eliminating heading conflicts that break strict locators

This doc is a clean-room checklist so a fresh contributor can reproduce, understand, and fix issues without prior context.

## Preconditions
- Node 20 LTS
- npm
- Playwright browsers installed

## Current Symptoms (from Playwright report)
- Auth tests: duplicate h1 causes strict locator conflicts; user profile element not found
- Dashboard tests: metrics and health default to zeros; activity feed shows fallback
- Navigation tests: PM still sees admin-only items; mobile nav always visible; unauthorized routes not redirected

## Driver Tree (ordered changes)
1) Authentication (E2E-safe)
   - Add a first-class E2E mock mode that bypasses network and sets a mock account
   - Ensure `useAuth` respects mocked roles (`NEU_Admin` vs `NEU_PM`)
   - Provide a stable `[data-testid="user-profile"]` for UI assertions
2) Dashboard data alignment
   - Ensure endpoints match the tests’ routes and shapes
   - Render mocked values (via Playwright route fulfills) instead of fallback zeros
3) Navigation and RBAC
   - Role-based visibility (hide Templates/Users/Permissions/Audit for PM)
   - Unauthorized access redirects and shows an error message
   - Mobile nav is collapsed initially on small viewports and toggles correctly
4) A11y / Heading
   - Only one h1 per page; brand in shell should not be another h1

## Detailed Fix Plan

### 1) MSAL E2E Mock Mode
Relevant files:
- `web/src/config/auth.config.ts`
- `web/src/components/auth/AuthProvider.tsx`
- `web/src/hooks/useAuth.ts`
- `web/playwright.config.ts`
- E2E specs: `web/e2e/*.spec.ts`

Implementation points:
- Expose `isE2EMode()` that returns true if any of:
  - `import.meta.env.VITE_E2E === 'true'`
  - `window.__MSAL_MOCK__ === true`
  - `sessionStorage['mock-account']` exists
- In `AuthProvider`, when `isE2EMode()` is true, call `initialize()`, set a mock active account, and skip real login/redirect
- In `useAuth`:
  - `isAuthenticated` should be `accounts.length > 0 || isE2EMode()`
  - For roles in E2E mode: read from `sessionStorage['mock-account']` JSON `idTokenClaims.roles`
  - `login()` should early-return in E2E mode (no redirect)
  - `getAccessToken()` can return a stub value in E2E (`"mock-token"`) if needed by API clients
- In E2E `beforeEach`, set the mock flags and account:
```ts
await page.addInitScript(() => {
  (window as any).__MSAL_MOCK__ = true;
  window.sessionStorage.setItem('mock-account', JSON.stringify({
    username: 'admin@example.com',
    name: 'Admin User',
    idTokenClaims: { roles: ['NEU_Admin'] }
  }));
});
```

Playwright config:
- `use.baseURL = 'http://localhost:5173'`
- `webServer: { command: 'npm run dev', url: 'http://localhost:5173', reuseExistingServer: true }`

### 2) Dashboard Data Alignment
Relevant files:
- `web/src/pages/Dashboard.tsx`
- `web/src/components/dashboard/MetricCard.tsx`
- `web/src/components/dashboard/SystemHealth.tsx`
- `web/src/components/dashboard/ActivityFeed.tsx`

Endpoints expected by tests (and example shapes):
- `GET /api/orders?status=active` -> `{ count: number }`
- `GET /api/orders?status=pending_provision` -> `{ count: number }`
- `GET /api/orders?status=failed&since=24h` -> `{ count: number }`
- `GET /api/contracts?status=active` -> `{ count: number }`
- `GET /api/locks/summary` -> `{ timeLocked, crUnlocked, manualLocked }`
- `GET /api/guests?status=active` -> `{ count: number }` or `{ items: [...] }`
- `GET /api/health` -> `{ status, queueDepth, lastProvisionTime, latency }`
- `GET /api/audit/recent?limit=10` -> `[{ id, user, action, target, timestamp, type }, ...]`

Action items:
- Ensure the data layer calls the exact endpoints above
- Components should show loading states, then render values from responses (no permanent zeros)
- Health region should include status token (HEALTHY/DEGRADED/UNHEALTHY) and metrics like `3 jobs`, `5 min`, `150 ms`

### 3) Navigation, RBAC, and Mobile
Relevant files:
- `web/src/components/layout/Navigation.tsx`
- `web/src/components/layout/MainLayout.tsx`
- `web/src/components/auth/ProtectedRoute.tsx`

Role gating:
- Use `useAuth().userRoles` to render menu items conditionally
- For PM (`NEU_PM`) hide admin-only: Templates, Users & Groups, Permissions, Audit

Unauthorized routes:
- Keep `ProtectedRoute` logic; if access denied, display an error (e.g., `Unauthorized`) then `Navigate` to `/dashboard`

Mobile nav:
- On ~375x667, the nav should be hidden by default
- Provide a toggle button: `aria-label="Open navigation menu"`
- Toggling shows nav; clicking an item auto-closes

### 4) A11y / Heading Hierarchy
- Ensure only one `<h1>` per page
- On Dashboard, the content h1 should be `Dashboard`
- The app shell brand/title must not be `<h1>` if the page already has one; use `<h2>` or `role="heading" aria-level="2"`
