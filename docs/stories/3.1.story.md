# Story 3.1: Time-Based Locking System and Scheduler

## Status
go

## Story
**As an** Admin,
**I want** to configure and enforce time-based folder access rules with automatic state transitions,
**so that** documents are locked/unlocked according to project timelines and deadlines are enforced

## Acceptance Criteria
1. Time-based lock rules can be configured with T-relative windows (T-3, T+0, T+8 etc.)
2. Scheduled job evaluates and applies lock state transitions every 15 minutes
3. Lock states transition automatically: Full access → Limited → Read-only
4. T+0 release, T+1-7 upload window, T+8 automatic read-only lock
5. Lock transitions are idempotent and re-entrant safe
6. All state transitions are audited with timestamp and reason
7. Scheduler reliability ≥99% with monitoring and alerting
8. Time windows support both relative (T+n) and absolute dates

### Data Models
New tables for time-based locking [Source: architecture/7-data-model-postgresql-15.md]:
- `lock_rule` - Time-based lock configurations per EM
- `lock_state` - Extended from story 2.2 for time-based locks
- `lock_transition_log` - History of state changes

Schema design:
```sql
CREATE TABLE lock_rule (
  id UUID PRIMARY KEY,
  order_em_id UUID REFERENCES order_em(id),
  rule_name VARCHAR(100),
  t_value DATE, -- The T+0 reference date
  window_type VARCHAR(50), -- pre_release, active, limited, locked
  start_offset INTEGER, -- Days relative to T (can be negative)
  end_offset INTEGER, -- Days relative to T
  permission_level VARCHAR(20), -- full, write, read
  created_by UUID REFERENCES users(id),
  created_at TIMESTAMP WITH TIME ZONE
);

CREATE TABLE lock_transition_log (
  id UUID PRIMARY KEY,
  lock_rule_id UUID REFERENCES lock_rule(id),
  folder_path TEXT,
  previous_state VARCHAR(50),
  new_state VARCHAR(50),
  transitioned_at TIMESTAMP WITH TIME ZONE,
  evaluation_run_id UUID,
  success BOOLEAN,
  error_message TEXT
);
```
