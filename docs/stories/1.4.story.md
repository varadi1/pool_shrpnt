# Story 1.4: Template Versioning, Diff, and Rollback

## Status
Ready for Review

## Story
**As an** Admin,
**I want** to version, compare, and rollback folder templates,
**so that** I can safely manage template changes without affecting existing provisioned EMs

## Acceptance Criteria
1. Template versioning system tracks all template changes with version numbers
2. Publishing a new template version does not affect existing provisioned EMs
3. Template diff functionality shows changes between any two versions
4. Rollback functionality allows reverting to previous template versions
5. Template validation ensures all required fields are present before publishing
6. Version history is maintained with author, timestamp, and change description
7. API endpoints support template version management operations
8. Template changes trigger audit events with full change details

### Data Models
Extend existing models [Source: architecture/7-data-model-postgresql-15.md]:
- `folder_template` - Add version, status (draft/published), current_version flag
- `folder_template_version` (new) - Complete version history with snapshots
- `order_em` - Add template_version_id to lock template at provisioning time

Database schema changes:
```sql
-- Extend folder_template
ALTER TABLE folder_template ADD COLUMN version VARCHAR(20);
ALTER TABLE folder_template ADD COLUMN status VARCHAR(20) DEFAULT 'draft';
ALTER TABLE folder_template ADD COLUMN parent_version_id UUID;
ALTER TABLE folder_template ADD COLUMN is_current BOOLEAN DEFAULT false;

-- New version history table
CREATE TABLE folder_template_version (
  id UUID PRIMARY KEY,
  template_id UUID REFERENCES folder_template(id),
  version VARCHAR(20) NOT NULL,
  content JSONB NOT NULL, -- Full template snapshot
  author_id UUID,
  created_at TIMESTAMP WITH TIME ZONE,
  change_description TEXT,
  parent_version_id UUID
);
```

### Technical Constraints
[Source: architecture/coding-standards.md and prd/5-felhasznli-trtnetek-top-10-s-elfogadsi-kritriumok.md]:
- Published templates must be immutable
- Version numbers follow semantic versioning (MAJOR.MINOR.PATCH)
- All changes must be audited with full before/after state
- Diff output must be human-readable
- Rollback creates new version, doesn't modify history
- Template validation before publishing is mandatory
- No retroactive changes to provisioned EMs

Template versioning principles:
- Draft templates can be modified freely
- Publishing creates immutable version snapshot
- Each EM locks to specific template version at provisioning
- Version history is append-only (no deletions)
- Rollback is forward-only (creates new version from old)
