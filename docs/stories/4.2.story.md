# Story 4.2: Guest Access Revocation and Lifecycle Management

## Status
go

## Story
**As an** Admin,
**I want** to revoke guest access and manage guest user lifecycle including expiration,
**so that** I can maintain security by removing access when no longer needed and enforce guest access policies

## Acceptance Criteria
1. Admin can revoke guest access immediately through the UI with reason tracking
2. Revocation removes guest from all Azure AD groups and SharePoint/Teams permissions within 1 minute
3. System enforces automatic guest expiry based on configurable policy (default 90 days)
4. Admin receives notifications 7 days before guest expiry for review/extension decision
5. Guest access can be extended for additional periods with justification
6. Revoked guests are retained in database with status but removed from Azure AD after 30 days
7. All lifecycle events are audited: GUEST_REVOKED, GUEST_EXPIRED, GUEST_EXTENDED, GUEST_PURGED
8. Bulk operations supported for revoking multiple guests (e.g., all guests from a partner company)

### Technical Constraints
**Performance Requirements** [Source: architecture/coding-standards.md]
- Revocation effective within 1 minute (AC requirement)
- Bulk operations handle up to 100 guests
- Daily lifecycle checks complete within 5 minutes

**Database Migration Strategy**
- Use Alembic for schema migrations
- Always include rollback in migration:
  ```python
  def upgrade():
      # Add lifecycle fields
      op.add_column('guest_user', sa.Column('expires_at', sa.DateTime()))
      
  def downgrade():
      # Remove lifecycle fields
      op.drop_column('guest_user', 'expires_at')
  ```
- Test migrations on staging before production
- Backup database before migration execution

**Security Requirements** [Source: architecture/13-security-compliance.md]
- Immediate access removal on revocation
- Audit all permission changes
- Purge guest data per retention policy
- No orphaned permissions in SharePoint/Teams

### UI Interaction Flows

**Guest Revocation Flow:**
1. Admin clicks revoke icon in guest list
2. Confirmation modal appears with reason field
3. Admin enters reason (required) and confirms
4. Loading state while API call executes
5. Success toast: "Guest access revoked successfully"
6. Guest row updates to show REVOKED status
7. Audit event logged with admin ID and reason

**Guest Extension Flow:**
1. Admin views guest approaching expiry (yellow indicator)
2. Clicks "Extend" button in actions column
3. Extension form opens with current expiry displayed
4. Admin selects new date and enters justification
5. System validates against max extension policy
6. Success: Updates expiry date and resets indicator
7. Failure: Shows policy violation message

**Bulk Revocation Flow:**
1. Admin selects checkboxes for multiple guests
2. Bulk action toolbar appears at top
3. Clicks "Revoke Selected (N)" button
4. Confirmation dialog lists all selected guests
5. Admin enters common reason for all
6. Progress bar shows revocation progress
7. Summary shows success/failure count
